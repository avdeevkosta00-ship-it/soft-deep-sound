# Soft&Deep Sound — архитектура

## Стек и почему он

**Electron + чистый JS (ES-модули) + Web Audio API.**

- Все «звуковые» фичи (Pitch, эмбиент, дакинг, BPM, визуалайзер) — это нативные возможности Web Audio: `AudioWorklet`, `AnalyserNode`, `OfflineAudioContext`. В Qt/WPF/Flutter то же самое пришлось бы писать на C++/NAudio/FFI.
- Интерфейс с размытием стекла, хромом и анимациями — это CSS (`backdrop-filter`, градиенты, анимация `d` у SVG-путей), так что дизайн можно менять, не трогая логику.
- Сборка установщика и portable-версии для Windows делается одной командой (`electron-builder`).

```
main process (Node)                          renderer (Chromium, sandbox)
├─ sds:// протокол  ── app файлы ─────────►  index.html / styles.css / js/*
│                   ── media (Range) ──────►  <audio> → Web Audio граф
├─ library.json  (атомарная запись)    ◄──►  состояние: треки, плейлисты, настройки
├─ music-metadata (теги, обложки)       ◄──  импорт: диалог / drag&drop / «Открыть с помощью»
├─ search/providers.js  (HTTP к API)    ◄──  гибридный поиск
└─ search/downloader.js (проверки)      ──►  файл в «Музыка/Soft&Deep Sound» → в медиатеку
```

### Аудиограф

```
<audio> → MediaElementSource ─┬→ PitchShifter (AudioWorklet) → fade → master → выход
                              │                                  └→ analyser → визуалайзер
                              └→ voiceAnalyser (до эффектов) → Smart Duck
Эмбиент-слои (процедурные лупы) → ambientBus → duck gain → master
```

- **Sound Pitcher.** Сдвиг тональности без изменения темпа: двухголовочная вращающаяся линия задержки (головки читают со скоростью `ratio`, окна sin² в сумме дают 1). Есть режим **VINYL** — классический varispeed, когда тон и темп меняются вместе. Включение и выключение плавное, с одинаковой задержкой, так что трек не «прыгает».
- **Ambient Generator.** Дождь, винил, костёр и поезд синтезируются кодом, без файлов-сэмплов, в бесшовные стерео-лупы. У винила луп кратен 33⅓ об/мин, у поезда стук «та-дам… та-дам» соответствует 25-метровым рельсам. **Smart Duck** следит за энергией вокальной полосы (300–3400 Гц) относительно средней громкости трека и всего спектра. Атака быстрая (~50 мс), отпускание медленное (~0,4 с). Это эвристика, а не нейросеть: громкий синт-лид в той же полосе тоже вызовет приседание.
- **BPM.** Трек декодируется в отдельном `OfflineAudioContext` на 22 кГц, анализ идёт в Web Worker. Шаги: огибающая онсетов (поток энергии низкой и высокой полос, шаг 10 мс) → автокорреляция с гребнем ×2/×3 → априорное распределение вокруг 120 BPM против ошибок «вдвое» → параболическая интерполяция → поиск фазы долей. Та же задача строит пики для волновой полосы перемотки. Результат кешируется в медиатеке, и повторно трек не декодируется. Если темп всё же определился неверно, есть кнопки TAP, ×½ и ×2.

## Гибридная поисковая строка

### 1. Архитектура: WebView-парсинг или бэкенд-парсер?

**Бэкенд в main-процессе с API-провайдерами.** Встроенный WebView с инжекцией JS — так делать не стоит.

| | WebView + инжект JS | HTTP/API в main-процессе ✅ |
|---|---|---|
| Безопасность | Чужие страницы с их JS и рекламой исполняются внутри приложения | В приложение попадает только JSON. Чужой HTML никогда не рендерится |
| Стабильность | Ломается при любой правке вёрстки сайта | API версионируются, есть контракт |
| CORS | Его приходится обходить хаками | В Node CORS отсутствует как класс: это браузерное ограничение |
| Скорость | Загрузка целых страниц | Один-два JSON-запроса, источники опрашиваются параллельно |
| Легальность | Скрейпинг часто нарушает ToS сайтов | Официальные API с явными лицензиями |

Реализация — `src/search/providers.js`. Каждый провайдер — объект `{ key, label, search(query, settings) }`, который возвращает нормализованный `Result` (`title, artist, fileUrl, pageUrl, license, format, duration`). `searchAll()` опрашивает всех параллельно через `Promise.allSettled`, поэтому медленный или упавший источник не блокирует остальные. Затем дубли убираются по URL файла, и результаты ранжируются по совпадению с запросом. Добавить источник = дописать один объект.

Подключённые источники (все отдают **прямые ссылки на файлы** с открытыми лицензиями):

- **Openverse** (`api.openverse.org/v1/audio`) — агрегатор CC-аудио (Jamendo, Freesound, Wikimedia и др.), ключ не нужен.
- **Internet Archive** (`advancedsearch.php` + `/metadata/{id}/files`) — концерты, net-лейблы, public domain.
- **Jamendo API** — включается, если в настройках указан бесплатный `client_id`.

### 2. Безопасность и легальность

**CORS** обходить не нужно: все сетевые запросы делает main-процесс через `net.fetch` (он учитывает системный прокси), а renderer получает готовые данные через узкий IPC-мост.

**Защита от вредоносного контента** — `src/search/downloader.js`, единственный путь, которым байты из сети попадают на диск:

1. только `https://`, без IP-литералов и `localhost` (защита от SSRF), цель редиректа проверяется заново;
2. `Content-Type` должен быть `audio/*` (или octet-stream с аудиорасширением);
3. жёсткий лимит размера (300 МБ), запись потоком во временный `.part`;
4. **проверка сигнатуры**: файл должен реально начинаться как MP3/FLAC/OGG/WAV/M4A/WebM, и расширение берётся из сигнатуры, а не из URL. Переименованный `.exe` будет отклонён;
5. имя файла санитизируется, существующие файлы не перезаписываются.

Плюс общий харденинг Electron: `contextIsolation`, `sandbox`, `nodeIntegration: false`, строгий CSP, запрет навигации и всплывающих окон (внешние ссылки открываются в системном браузере, только https), протокол `sds://media` отдаёт только аудиофайлы и кеш обложек.

**Сторы и закон.** Это десктопное приложение, Google Play и App Store к нему не относятся. Если появится мобильная версия: Apple (Guideline 5.2.3) и Google (политика об IP и «Unauthorized use of copyrighted content») отклоняют приложения, которые помогают скачивать музыку с нелицензионных ресурсов. Обёртка «In-App Browser» от этого **не спасает**: ревьюеры оценивают функцию, а не её название. Работающий путь — тот, что реализован здесь: поиск только по источникам с явной лицензией, лицензия видна у каждого результата, есть ссылка на страницу автора. Произвольный скрейпинг «где угодно найти mp3» я сознательно не делал: он почти всегда упирается в пиратские сайты, нарушает их ToS и делает приложение непубликуемым. *Я не юрист — для коммерческого релиза стоит отдельная юридическая проверка.*

### 3. UI/UX: одно поле для двух миров

- Строка всегда наверху (**Ctrl+K** или `/`). При вводе сразу появляется выпадающий список: секция **«В медиатеке»** (мгновенно, с подсветкой совпадений; ↵ — играть) и последняя строка **«Найти … в открытых источниках»**.
- Справа в поле — индикатор области поиска: `ЛОКАЛЬНО` → `ЛОКАЛЬНО + СЕТЬ` → `СЕТЬ` (оранжевый, если локально ничего нет: Enter сразу уйдёт в сеть). **Shift+Enter** всегда ищет в сети.
- Экран результатов поиска: сначала локальные треки (обычный трек-лист), ниже — веб-результаты со скелетон-загрузкой. У каждого видны источник, лицензия, формат и длительность; кнопки «прослушать», «страница источника» и «Скачать» с прогрессом прямо внутри кнопки.
- После скачивания трек сразу попадает в медиатеку, а тост предлагает положить его в плейлист — тот же сценарий, что и при обычном импорте.

### 4. Базовый алгоритм (упрощённо, полная версия — в `providers.js` / `downloader.js`)

```js
// main process
async function hybridSearch(query) {
  query = query.trim().slice(0, 200);
  const providers = [openverse, internetArchive, jamendo].filter(p => p.enabled?.(settings) ?? true);
  const settled = await Promise.allSettled(providers.map(p => p.search(query)));

  const seen = new Set(), results = [];
  for (const s of settled) {
    if (s.status !== 'fulfilled') continue;            // упавший источник просто пропускаем
    for (const r of s.value) {
      if (!/^https:\/\//.test(r.fileUrl)) continue;     // только https
      if (!/\.(mp3|ogg|flac|wav|m4a)(\?|$)/i.test(r.fileUrl) && !r.format) continue; // только аудио
      if (seen.has(r.fileUrl)) continue;                // без дублей
      seen.add(r.fileUrl);
      results.push({ ...r, score: relevance(query, r.title, r.artist) });
    }
  }
  return results.sort((a, b) => b.score - a.score);
}

// пример провайдера: запрос → JSON → прямые ссылки
const openverse = {
  async search(q) {
    const res = await net.fetch(`https://api.openverse.org/v1/audio/?q=${encodeURIComponent(q)}`);
    const { results } = await res.json();
    return results.map(r => ({ title: r.title, artist: r.creator, fileUrl: r.url,
      pageUrl: r.foreign_landing_url, license: `${r.license} ${r.license_version}` }));
  }
};

// скачивание: https → Content-Type audio/* → лимит → сигнатура → сохранить
```

## Spotify и Яндекс Музыка (почему не встроены)

- **Spotify.** Официальный путь — Web Playback SDK. Он требует Premium-аккаунт и регистрацию приложения у Spotify, а с 2025 года расширенный доступ к API выдаётся только организациям. Поток защищён DRM (Widevine): обычный Electron его не воспроизводит, нужна специальная сборка с подписью VMP. Главное: защищённый звук нельзя пропустить через Web Audio, поэтому Pitch, эквалайзер, Ambient-дакинг и визуалайзер на нём работать не будут. Реалистичный вариант — **Spotify Connect как пульт**: показывать текущий трек и управлять воспроизведением на устройстве пользователя через Web API.
- **Яндекс Музыка.** Публичного API нет. Существующие библиотеки построены на реверс-инжиниринге, противоречат пользовательскому соглашению и могут привести к блокировке аккаунта.

## v1.2: поиск по любой ссылке

`src/search/extract.js`. Пользователь сам вставляет ссылку (в поисковую строку или в карточку под результатами):
- если это прямой файл — сразу один результат;
- если страница — HTML читается в main-процессе как текст (не рендерится и не исполняется), и из него собираются все аудио, которые страница отдаёт сама: `og:audio`, `<audio>/<source>`, JSON-LD `contentUrl`, ссылки и URL на .mp3/.ogg/.flac/.m4a/.wav/.opus.

Скачивание идёт через тот же `safeDownload` (https, `audio/*`, сигнатура, лимит), с Referer страницы — многие хостинги без него не отдают файл. Автоматического «обхода всего интернета» в поисках копий нет: он почти всегда упирается в пиратские сайты.

Плееры, которые подгружают звук скриптом после открытия (стриминговые сервисы, многие соцсети), из HTML не видны — это ограничение «без браузера» и защита этих сервисов.

## v1.2: цвет свечения от обложки

`coverColor()` в `app.js` уменьшает обложку до 40×40 и строит гистограмму оттенков, взвешенную по насыщенности. Серые, почти чёрные и почти белые пиксели пропускаются. Победивший оттенок доводится до «светящейся» насыщенности и яркости и задаётся как `--pulse` (зарегистрированное `@property`, поэтому цвет плавно перетекает между треками) для фонового свечения, кольца Play и ореола обложки. Монохромные обложки используют акцент темы.

## v1.4: анализ звука, похожие, умная сессия, здоровье медиатеки

- **Анализ** (`renderer/js/bpm-worker.js`, Web Worker): кроме BPM и волны считает тональность (FFT → хрома → профили Krumhansl–Kessler, вывод и в нотации Camelot), громкость LUFS по BS.1770 (K-взвешивание + гейтинг), пиковый уровень и динамику (PLR), а также энергию, долю баса, «вокальной» полосы и яркость. Результат помечается `av: 2`. Фоновый анализ идёт по одному треку, с паузами, чтобы не мешать воспроизведению; отключается в настройках.
- **Похожие** (`smart.js → similarity`): взвешенная близость темпа (учитывая половинный/двойной), совместимость тональностей по кругу Camelot, близость энергии/спектра/громкости, жанр и исполнитель. Каждая рекомендация показывает причины.
- **Умная сессия** (`smart.js → buildSession`): цели настроения → отбор кандидатов → фильтры (темп, недавно игравшие, лимит исполнителя подряд) → упорядочивание «ближайший сосед», чтобы переходы были плавными.
- **Здоровье медиатеки** (`smart.js → healthReport`): кракозябры исправляются переинтерпретацией строки как cp1251, дубликаты — по нормализованному названию+исполнителю и длительности ±4 с (лучшим считается lossless/больший битрейт), пропавшие файлы проверяются через `library:existsMany`, качество — через `library:formatInfo` (music-metadata). Файлы на диске не изменяются — правки хранятся только в базе плеера.
- **Погружение** (`deepview.js`): FLIP-анимация общей обложки (Web Animations API), фон из размытой обложки, учитывает `prefers-reduced-motion`.

## v1.5: экспорт с эффектами и визуальный язык Soft&Deep

- **Экспорт** (`renderer/js/exporter.js`): трек декодируется и прогоняется через `OfflineAudioContext` с тем же pitch-worklet (стартует сразу с нужным коэффициентом, задержка 1/2 зерна обрезается), копией 10-полосного EQ и слоями эмбиента. Smart Duck воспроизводится заранее рассчитанной огибающей по полосе 300–3400 Гц (тот же закон атаки/спада, что и вживую). Если сумма перегружает 0 dBFS — уровень снижается до −0,3 dBFS. WAV пишется с TPDF-дизерингом и тегами LIST/INFO, MP3 кодируется LAME в отдельном worker'е + ID3v2.3. Записать файл можно только по пути, выбранному в системном диалоге сохранения (`export:pick` → `export:write`).
- **Soft / Deep**: палитра холодное серебро + aqua/cyan, оранжево-красный (`--hot`) только для Play, играющего трека и индикатора. Переключение — View Transitions API (круг от переключателя). Фон — `bg.js → aero()`, визуализатор — «световая волна», полноэкранный режим — `visual.js`.

## v1.6: новый дизайн Soft и Deep

Стили тем вынесены в `renderer/themes-sd.css`. **Soft** («Soft Club»): небо, кобальт `#1f45e8`, широкий шрифт Unbounded в нижнем регистре, HUD-детали (перекрестия, линейка, нумерация разделов, штрихкод, readout «▶ 00:45 ——• 001»). **Deep** («Glass Noir»): чёрное стекло, тонкие обводки-«пилюли», неоновый градиент розовый → фиолетовый → синий. Фон (`bg.js → sky() / noir()`): стеклянная сфера, которая дышит в покое и пульсирует с басом, плюс несколько маленьких пузырей; в Deep через сферу проходит неоновая лента. Обложка в плеере — вращающийся диск с кольцом текста.

## v1.7: живые формы и новый набор тем

`renderer/js/shapes.js` — WebGL: большая сфера из ~11 000 точек (или ~26 000 «игл» в Обсидиане) и 5 маленьких форм. Поверхность смещается анимированным 3D simplex-шумом (2 октавы) прямо в вершинном шейдере, нормаль считается численно, освещение — ламберт + блик + rim. В покое формы «дышат», с музыкой бас увеличивает радиус и глубину деформации. Маленькие формы блуждают: направление каждой медленно случайно меняется, у краёв мягко разворачиваются. Цвета, режим (dots/spikes) и смешивание (add/alpha) задаются CSS-переменными темы `--shape-*`. Если WebGL недоступен, `bg.js` рисует прежние 2D-пузыри. При медленной отрисовке число точек автоматически уменьшается вдвое.

Темы: Soft, Deep, Pearl, Obsidian. Оформление описано по тону (`html[data-tone="light|dark"]` в `themes-sd.css`), а темы различаются только переменными в `styles.css`. Старые темы (Runner, Night, Aurora, Hi-Fi) удалены; сохранённый выбор переводится на ближайшую новую.

## v1.8: трей, фоновая работа, умный поиск

- **Трей** (`main.js`): закрытие окна прячет его (`closeToTray`, хранится в `userData/prefs.json`), выход — из меню трея. Состояние плеера renderer шлёт в `media:state`, команды приходят обратно через `media:cmd`. Кнопки миниатюры на панели задач — `setThumbarButtons`. `backgroundThrottling: false` — таймеры не замедляются, пока окно скрыто. Media Session API даёт системную плашку Windows и мультимедийные клавиши.
- **Локальный поиск** (`renderer/js/fuzzy.js`): транслитерация кириллица↔латиница, исправление раскладки, опечатки (Дамерау–Левенштейн), слитные слова, поиск по жанру и имени файла, ранжирование по полю и прослушиваниям.
- **Веб-поиск** (`src/search/match.js`): очистка запроса от «official video», «скачать», «feat.» и т. п., исправление раскладки, повтор транслитом, если первый запрос дал мало, нечёткая оценка релевантности.

## v1.9: надёжность

- Загрузка трека отменяемая (`AudioEngine.load` отклоняется при ошибке/таймауте, новая загрузка прерывает старую); битые файлы пропускаются, пауза больше не «догоняет» нажатое следом «играть».
- Удаление играющего трека, перемешивание с добавлением в очередь, восстановление позиции очереди после перезапуска, ручные правки тегов при повторном импорте — исправлены.
- Main: сохранения библиотеки идут строго по очереди, проверка путей через `path.relative`, обход папок без симлинк-петель и с лимитами, асинхронная проверка файлов, сохранение размера/положения окна, таймер сна, автозапуск (`--hidden`), выключение Windows не блокируется треем.
